MTS7 trust chain

An MTS7 chain has only two boxes. The root certificate is the card issuer's public key, which the terminal already holds. The card certificate is stored on the chip and sits inside the root's box. The issuer's seal on door 2 proves integrity. The chip's live seal on door 3 proves authenticity.

The terminal starts with a root key it already trusts

A traveller taps a card on a validator. The terminal selects the BoB application (AID A0 00 00 07 81 01) and reads the card certificate with GET DATA. MTS7 lets anyone read it, so it proves nothing yet. The root is not on the card. The terminal brought it.

    Reading the plan

    Two certificates, no intermediate

    The root certificate is the outer box and the card certificate is the inner one. The card issuer signs every card certificate directly with the root private key.

    Door 2 is integrity

    The issuer's signature covers everything in the card certificate, including the card public key. Change any of it and door 2 stays shut.

    Door 3 is authenticity

    Anyone can read and copy the card certificate. Only the real chip can sign a fresh challenge, because its private key cannot be read out.

    What's in each box

    In the BoB specifications, the root is the issuer's public key, published as a JWK in the Participant Metadata Set (MTS4). The card certificate is an ID MTB (MTS1), which MTS7 stores in the Cardholder certificates data object.
